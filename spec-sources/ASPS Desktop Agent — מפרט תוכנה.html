Desktop Agent — מפרט תוכנה מלא

גרסה: 0.1.1.1 פלטפורמה: Windows 10/11 שפה: Python 3.11 מיקום: apps/desktop/win/src/ תאריך: יולי 2026

01 סקירה כללית

ה-Desktop Agent הוא תהליך Windows הרץ ברקע ומהווה את הזרוע המקומית של מערכת ASPS. תפקידו לזהות חיבורי גישה מרחוק (AnyDesk, TeamViewer וכד'), לבדוק URLs חשודים, לתקשר עם ה-Backend בענן, ולהתאם לתוסף Chrome המוצמד לדפדפן.

האיום המרכזי שהמערכת מגנה מפניו: רמאי מחייג לקורבן, משכנע אותו להתקין אפליקציית גישה מרחוק, ואז ניגש לחשבון הבנק שלו. ה-Agent מזהה את החיבור הנכנס בזמן אמת ומפעיל התראה.

אחריות עיקרית

  • Remote Access Detection — ניטור AnyDesk/TeamViewer/RustDesk/RDP ו-7 אפליקציות נוספות
  • URL Analysis — בדיקת URLs שה-Extension שולח, תוך שימוש בcache מקומי ובקריאה לBackend
  • ImmediateDanger Mode — מצב חירום כאשר session נכנס פעיל ויש דפדפן עם כניסה לאתר רגיש
  • Extension Relay — WebSocket server מקומי לתוסף Chrome; ממסר נתוני tabs, תוצאות ניתוח, ואירועי גישה מרחוק
  • Browser History Scanning — סריקת היסטוריית Chrome/Edge/Firefox כל 30 שניות
  • Windows UI — System Tray, Popup סטטוס, ו-CenteredToast (חלון ImmediateDanger)

02 ארכיטקטורה

מבנה תהליכים

ה-Agent רץ כתהליך Python בודד. ה-UI (pystray + customtkinter) רץ ב-Main Thread. כל הלוגיקה האסינכרונית רצה ב-Thread נפרד עם asyncio event loop. תקשורת ZMQ SUB (Backend notifications) רצה ב-daemon thread משלה.

Log Watcher Threadsאחד לכל קובץ log שנצפה (AnyDesk, TeamViewer, VNC...)

06 שירותים

ZMQClient

ממשק יוצא לBackend. כל שליחה: connect() → send() → recv() → close(). ה-socket לא נשמר בין קריאות. threading.Lock מסדר גישה.

מתודהתיאור
send_request_token(device_uid, email)אימות מכשיר; מקבל טוקן + מפתח CURVE
send_refresh_token(device_uid, old_token)חידוש טוקן שפג
send_url_alert(...)בדיקת URL חשוד
send_track_url_alert(...)אירוע ניווט בדפדפן
send_remote_access_alert(...)שינוי מצב גישה מרחוק + כל השדות
send_tab_closed_alert(tab_id, url, ip)טאב נסגר (בזמן ImmediateDanger)
send_tab_changed_alert(tab_id, url, ...)URL שונה בטאב (בזמן remote control)
set_server_public_key(key)הפעל CURVE; clear_server_public_key() לנטרל
ℹ
Priority elevation: כאשר danger_mode.active == True, כל ה-alerts יוצאים עם Priority=CRITICAL, ללא קשר למה שהקורא ביקש.

NotificationClient

ZMQ SUB socket. מנוי על topic "device:{DeviceUid}". רץ ב-daemon thread. RCVTIMEO=5000ms. לוג heartbeat כל ~2 דקות בשקט.

ExtensionServer

WebSocket server. מנסה פורטים לפי EXTENSION_PORTS. מנהל multi-client (כמה חלונות Chrome יכולים להתחבר). הודעות heartbeat_ping, keepalive, browser_tabs_response — מטופלות בתוכו ולא מועברות.

request_browser_tabs(timeout=3.0): שולח get_browser_tabs לכל לקוח, ממתין ל-Futures, ממזג תוצאות.

AuthManager

מתודהתיאור
ensure_authenticated(max_retries=3)עם exponential backoff 2/4/8 שניות
authenticate()RequestToken; פותח דפדפן ל-DeviceLogin אם DeviceNotRecognized
refresh_token()RefreshToken; fallback ל-authenticate() אם נכשל
handle_auth_response(response)מזהה InvalidToken/TokenExpired ב-alert response; מבצע re-auth ומחזיר True/False
is_expired()בודק פקיעה עם buffer של 5 דקות
get_token()מחזיר טוקן רק אם valid; None אחרת

MonitorService

מתאם את כל asyncio tasks. start() מפעיל 3 tasks:

Taskמרווחתיאור
_monitor_remote_access()adaptive (1/2/5/30s); 3s בdangerloop ראשי לזיהוי RA; מעבד StateChange
_monitor_browser_history()30sסורק היסטוריית SQLite של Chrome/Edge/Firefox
_update_tray_status()5sמרענן תמונת tray וסטטוס popup

Adaptive Poll Intervals

מרווחמצב
1spending debounced close/session-end (תגובה מהירה לשינוי)
2sAnyDesk רץ (log parser lag compensation)
5sאפליקציית RA פעילה / session פתוח
30sidle — אין אפליקציות RA
3s (override)danger_mode.active == True

ScanService

זרימת בדיקת URL: Cache hit → return. אחרת: auth check → send_url_alert → process_response. Local URLs (localhost/127.x/::1) מדולגים ללא קריאה לBackend. על InvalidToken/TokenExpired בתשובה: re-auth ו-retry אחד.

BrowserTabsPolicy

Singleton thread-safe. מצבים: incoming_only (ברירת מחדל) / always / never. Backend יכול לשלוח SetBrowserTabsPolicyNotification עם ValidUntil לעקוף זמנית. ה-override מנקה את עצמו עם פקיעה.

DangerMode

Singleton thread-safe עם activate() / deactivate(). כאשר active:

  • ZMQClient — Priority=CRITICAL על כל alert
  • DebouncedStateTracker — עוקף debounce (שינויי session מדווחים מיד)
  • MonitorService — poll קבוע 3s
  • DeviceInfo.ImmediateDanger = True בכל הודעה

ProtectionService

מבצע ProtectiveActions שמגיעות מBackend. BlockRemoteAccess → קורא ל-RemoteAccessMonitor.disconnect_remote_session("anydesk") → AnyDesk.exe --disconnect.

לפני התחלת tail threads, קורא 500 שורות אחרונות מכל log files, ממיין לפי timestamp, ומעביר דרך SessionTracker. Sessions שהתחילו מעל 10 דקות לפני Startup נמחקים מיד.

סדר עדיפויות:

  2. Network Topology — ESTABLISHED connection: local port ב-listen_ports → INCOMING; remote port → OUTGOING
  3. AnyDesk connection_trace.txt — fallback לרשומות תוך 30 דקות
  4. System port scan — לאפליקציות המנוהלות ע"י svchost (כמו RDP)

10 ImmediateDanger Mode

מה מפעיל

Backend שולח ImmediateDangerNotification כאשר: session RA נכנס פעיל ואתר רגיש (בנק/קריפטו/ממשל וכד') פתוח בדפדפן והמשתמש מחובר (LoggedIn==true מהExtension).

5 שלבי ה-Handler (notification_handler)

  1. danger_mode.activate() — כל האפקטים המתוארים בסעיף 6
  2. start_immediate_danger_loop() — task כל 10s: אוסף tabs → שולח RemoteAccessAlert מלא
  3. _build_immediate_danger_details() — מחלץ danger_key, sensitive_url, protective_actions
  4. show_display_notification_actions() — CenteredToast ב-LOCKED mode (אדום, ללא כפתור סגירה, always-on-top, תוך 2s lift loop)
  5. broadcast immediate_danger_started — Extension עובר למצב ImmediateDanger, שולח tab_closed/tab_changed על כל אירוע
!
כל שלב עטוף ב-try/except — כישלון באחד לא מבטל את השאר. המשתמש מוגן גם אם UI נכשל.

סגירת ImmediateDanger

Backend שולח ImmediateDangerEndedNotification בשני תרחישים:

  • Session RA הסתיים
  • האתר הרגיש נסגר / המשתמש התנתק (Backend מזהה HasSensitiveBrowserPages=false ב-periodic alert)

ה-Handler: danger_mode.deactivate() → עצור loop → transform_to_cleared() (אותו חלון, עכשיו ירוק עם כפתור Close) → broadcast לExtension.

Extension בזמן ImmediateDanger

Agent שולח set_remote_controlled: true → Extension שולח לAgent על כל:

  • tab_closed_alert — כל סגירת טאב
  • tab_changed_alert — כל שינוי URL, עם isSensitiveWebsite ו-isLoggedIn

Agent מעביר אותם לBackend כ-TabClosedAlert / TabChangedAlert ללא המתנה ל-periodic tick.

11 אבטחה ואימות

Device ID

נוצר פעם אחת ב-hardware_id.py. פורמט: PC-{16 hex chars של SHA-256}. מקור: Win32_BaseBoard + Win32_BIOS + Win32_DiskDrive → fallback ל-MachineGuid → fallback לplatform.node(). Cached ב-%APPDATA%\AntiScam\device_id.

CURVE ZMQ Encryption

🔑
כל תקשורת ZMQ (REQ/REP + PUB/SUB) מוצפנת עם CurveZMQ (X25519 + ChaCha20-Poly1305 ברמת transport).

זרימת CURVE:

  1. Agent קורא מפתח ציבורי שרת (Z85) מקובץ בסדר עדיפויות (ראה סעיף 3)
  2. ב-ZMQClient.connect(): מייצר ephemeral keypair (zmq.curve_keypair()), מגדיר CURVE_PUBLICKEY/SECRETKEY/SERVERKEY על ה-socket
  3. לאחר אימות ראשוני: container.apply_curve_keys() מעביר את המפתח גם ל-NotificationClient (SUB)
  4. אם התשובה ל-RequestToken/RefreshToken מכילה serverPublicKey, ZMQClient מתעדכן לקריאות הבאות
  5. המפתח לא נשמר ב-auth.json — נקרא תמיד מחדש מהקובץ בStartup

אחסון טוקן

שכבהפרטים
ראשי — OS KeyringWindows Credential Manager. Service: "AntiScamApp", Account: device_uid
Fallbackauth.json (עם אזהרה) כאשר keyring לא זמין
לא נשמרserver_public_key — מניעת שמירת מפתח CURVE בדיסק

מחזור חיי הטוקן

  1. Startup: ensure_authenticated(max_retries=3) עם backoff 2/4/8s
  2. כל בדיקת token: buffer פקיעה 5 דקות (is_expired())
  3. תשובת DeviceNotRecognized: פתיחת דפדפן ל-{WEBAPI_URL}/DeviceLogin?deviceUid={uid} (פעם אחת בלבד)
  4. תשובת InvalidToken/TokenExpired בזמן alert: handle_auth_response() → re-auth → retry פעם אחת
  5. אימות נכשל לחלוטין: background thread מנסה שוב כל 30s

נקודות תשומת לב אבטחה

⚠
חוב אבטחה ידוע:
• WebSocket לExtension רץ על ws:// (ללא TLS) — סיכון ל-localhost loopback interception
• ZMQ ports 5555/5556 ב-Backend כרגע bound ל-*: (ראה CLAUDE.md)
• WHITELIST_IPS hardcoded עם IP ספציפי (100.86.253.55) — לבדוק עם צמיחת infrastructure

14 Startup / Shutdown

רצף Startup

  1. get_or_create_device_id() — hardware fingerprint, cached לדיסק
  2. AntiScamApp.__init__() — Container DI, wireup callbacks
  3. extension_server.start() — WebSocket server על הפורט הראשון הפנוי
  4. auth_manager.ensure_authenticated() — עד 3 ניסיונות עם backoff
  5. container.apply_curve_keys() — מעביר CURVE key ל-NotificationClient
  6. notification_client.start() — daemon thread לZMQ SUB
  7. אם auth נכשל: _background_reconnect() thread — מנסה כל 30s
  8. monitor_service.start() — מפעיל 3 asyncio tasks
  9. remote_monitor.startup_scan() — בדיקת מצב נוכחי, שליחת alerts על מצבים קיימים
  10. tray_icon.run_blocking() — Main Thread blocking — pystray + customtkinter mainloop

רצף Shutdown

  1. Tray Exit / KeyboardInterrupt → _on_exit()
  2. self._running = False — asyncio loop מסתיים
  3. monitor_service.stop() — cancel לכל tasks
  4. extension_server.stop() — סגירת כל WebSocket clients
  5. notification_client.stop() — עצירת SUB thread, cleanup ZMQ
  6. zmq_client.destroy() — ביטול ZMQ Context
  7. tray.stop() — destroy popup, עצירת pystray, quit CTk root
ℹ
Build: build_release.py --env prod מעתיק config_prod.py → config_override.py, ואז PyInstaller יוצר EXE יחיד. Installer: Inno Setup. מתקין כ-AntiScam.exe תחת Program Files, רישום ב-Startup, סמל Desktop.
