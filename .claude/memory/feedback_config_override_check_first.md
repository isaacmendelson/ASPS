When the desktop agent uses wrong config values, check `config_override.py` first.

**Why:** `config.py` imports `from config_override import *` at the end (lines 414-415), giving `config_override.py` final say over every config value. This file is gitignored and environment-specific (generated by `build_release.py --env <name>`). A stale local `config_override.py` with `BACKEND_HOST = "127.0.0.1"` will silently override any change made to `config.py`.

**How to apply:** When debugging "desktop agent connects to wrong host" or similar config issues: (1) check `apps/desktop/win/src/config_override.py` exists and what it contains, (2) remember that `-B` (skip .pyc) won't help — it's not a cache issue, it's a Python import mechanism. The committed `config.py` keeps localhost defaults; all environment-specific values go in `config_override.py`.
