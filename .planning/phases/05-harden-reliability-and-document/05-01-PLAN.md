Add `_reset_socket()` method and refactor `send_alert()` to use Lazy Pirate retry pattern:

1. Add `_reset_socket(self)` method to ZMQClient:
   - Set `zmq.LINGER = 0` on socket before closing (prevents blocking)
   - Close socket, set `self.socket = None`
   - Create new REQ socket on the SAME context (do NOT call context.term())
   - Set RCVTIMEO = self.timeout on new socket
   - If curve_enabled and server_public_key, call `apply_curve_client()` on new socket
   - Connect new socket to `tcp://{self.host}:{self.port}`
   - Log: "ZMQ REQ socket reset (Lazy Pirate recovery)"

2. Refactor `send_alert()` to use retry loop with Lazy Pirate:
   - Add `retries` parameter (default=3)
   - Wrap the send/recv in a retry loop (for attempt in range(retries))
   - After `self.socket.send(message_bytes)`, use `self.socket.poll(self.timeout, zmq.POLLIN)` to check for response BEFORE calling recv
   - If poll returns True: call `self.socket.recv()` and process as before
   - If poll returns False (timeout): log warning with attempt number, call `self._reset_socket()`, continue to next attempt
   - On zmq.ZMQError: log error, call `self._reset_socket()`, continue
   - After all retries exhausted: return None
   - Remove the old `except zmq.Again` handler (poll replaces it)

3. Also update `close()` method:
   - Add `self.socket.setsockopt(zmq.LINGER, 0)` before `self.socket.close()` to prevent blocking during shutdown

Do NOT change `send_url_alert()`, `request_token()`, or `send_remote_access_alert()` -- they already do connect/close per call and benefit automatically from the improved `send_alert()`.

Why poll instead of recv with RCVTIMEO: poll does NOT change the socket state machine. If poll times out, we know no message arrived and can safely destroy the socket. With recv + RCVTIMEO, the socket is left in a corrupted "waiting for reply" state after timeout.

2. Add `PendingResults` class before `ExtensionServer`:
   ```python
   class PendingResults:
       """Store analysis results for delivery after Extension reconnects.
       Results are time-limited (5min TTL) and size-limited (50 max)."""
       def __init__(self, max_age_seconds=300, max_items=50):
           self._results = []  # list of (timestamp, message_dict)
           self.max_age = max_age_seconds
           self.max_items = max_items

       def store(self, message: dict):
           self._cleanup()
           self._results.append((time.time(), message))
           if len(self._results) > self.max_items:
               self._results.pop(0)
           logger.info(f"Stored pending result ({len(self._results)} total): {message.get('url', 'N/A')}")

       def flush(self) -> list:
           self._cleanup()
           results = [msg for _, msg in self._results]
           self._results.clear()
           return results

       def _cleanup(self):
           cutoff = time.time() - self.max_age
           self._results = [(t, m) for t, m in self._results if t > cutoff]

       @property
       def count(self):
           return len(self._results)
   ```

3. In `ExtensionServer.__init__()`, add: `self.pending_results = PendingResults()`

4. In `ExtensionServer._handle_client()`, right after `self.clients.add(websocket)` and the logging lines, add pending results delivery:
   ```python
   # Deliver pending results from while client was disconnected
   pending = self.pending_results.flush()
   if pending:
       logger.info(f"Delivering {len(pending)} pending results to reconnected client")
       for result in pending:
           try:
               await websocket.send(json.dumps(result))
               _diag_log("SEND", f"Delivered pending result: {result.get('url', 'N/A')}", result)
           except Exception as e:
               logger.error(f"Error delivering pending result: {e}")
   ```

   ```python
       return
   ```
