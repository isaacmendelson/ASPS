<objective>
Fix the thread-to-asyncio bridge in NotificationHandler so that broadcast coroutines are scheduled on the main asyncio event loop (where WebSocket clients are connected) instead of creating a new isolated loop via asyncio.run().

Purpose: This is the PRIMARY bug causing notifications to never reach the Chrome Extension. When NotificationHandler.handle() is called from the ZMQ background thread, it currently falls back to asyncio.run() which creates a new event loop with zero WebSocket clients. The fix uses asyncio.run_coroutine_threadsafe() to schedule the broadcast on the correct event loop, and injects the loop reference from main.py's async start() before the notification thread starts.

Output: Modified notification_handler.py with thread-safe bridge + diagnostic logging, and modified main.py with event loop injection.
</objective>
