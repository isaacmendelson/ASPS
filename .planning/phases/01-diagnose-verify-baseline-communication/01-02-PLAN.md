  <action>
    Create `apps/desktop/win/src/diag_ws_test.py` -- a self-contained diagnostic script that verifies the Desktop App's WebSocket server is reachable and responds to messages.

    1. Define a `diag_log(component, direction, message, data=None)` function identical to the one in diag_zmq_test.py: ISO-8601 UTC timestamps, `>>>` for SEND, `<<<` for RECV, optional JSON data indented.

    2. **Port scan** (async function `find_ws_port()`):
       - Try connecting to each port in `[8080, 8181, 8282, 8383, 8484]` using `websockets.connect()` with a 2-second timeout (`open_timeout=2`).
       - For each port, wrap in try/except. On success, close the connection and return the port number.
       - If no port responds, return None.
       - Log each attempt: `diag_log("WS-DIAG", "SEND", f"Probing port {port}...")`.

    3. **Ping/Pong test** (async function `test_ws_ping_pong(port)`):
       - Connect to `ws://localhost:{port}` using `websockets.connect()` with `open_timeout=5`.
       - Log connection: `diag_log("WS-DIAG", "SEND", f"Connected to ws://localhost:{port}")`.
       - Send `{"type": "ping"}` as JSON string.
       - Log: `diag_log("WS-DIAG", "SEND", "Ping message", {"type": "ping"})`.
       - Wait for response with `asyncio.wait_for(ws.recv(), timeout=5.0)`.
       - Parse response JSON.
       - Log: `diag_log("WS-DIAG", "RECV", "Pong response", response_dict)`.
       - Check if response has `"type": "pong"`. If yes: print "PASS: WebSocket ping/pong works." If no: print "WARN: Unexpected response type: {type}".
       - On timeout: print "FAIL: WebSocket response timed out after 5s."
       - On ConnectionRefused: print "FAIL: Connection refused on port {port}."
       - Always close connection in finally block.
       - Return True/False.

    4. **URL check simulation test** (async function `test_ws_url_check(port)`):
       - Connect to `ws://localhost:{port}`.
       - Send `{"type": "url_check", "url": "https://diagnostic-test.example.com", "trackers": [], "iframes": []}`.
       - Log the SEND with timestamp and payload.
       - Wait for response with 10-second timeout (URL check involves backend processing).
       - Log the RECV with timestamp and response.
       - Print the response regardless of content -- any response proves bidirectional communication.
       - NOTE: This test may fail if Backend is not running. That is OK -- print "INFO: url_check requires Backend connection. If this fails, verify Plan 01-01 passed first."
       - Return True/False.

    5. **Main block** (`if __name__ == "__main__"`):
       - Print header: `"=== ASPS Phase 1 Diagnostic: WebSocket Test ==="`
       - Call `find_ws_port()`. If None: print "FAIL: No WebSocket server found on ports 8080-8484. Start the Desktop App first." and exit with code 1.
       - Print the found port: `"Found WebSocket server on port {port}"`.
       - Call `test_ws_ping_pong(port)`.
       - Call `test_ws_url_check(port)` (best-effort, not a hard requirement).
       - Print summary footer with overall PASS/FAIL based on ping/pong result.

    Dependencies: Only `websockets`, `asyncio`, `json`, `datetime`, `sys` -- all already available.

    WHY: Provides automated diagnostic evidence that the WebSocket link is functional, without requiring the Chrome Extension to be installed/configured. The Chrome Extension test is the checkpoint task.

    ```python
    def _diag_log(direction: str, message: str, data: dict = None):
        """Phase 1 diagnostic logging at WebSocket boundary"""
        ts = datetime.datetime.utcnow().isoformat() + "Z"
        prefix = ">>>" if direction == "SEND" else "<<<"

    ```
