Modify `handle_message()` in extension_handler.py to run `_handle_url_check` via `loop.run_in_executor()` instead of calling it directly. This prevents the synchronous ZMQ I/O in `scan_service.check_url()` from blocking the asyncio event loop.

Specific changes:

1. Add imports at top of file:
   ```python
   import asyncio
   import functools
   ```

2. In `handle_message()` (line 38-40), replace the direct `return handler(data)` call with a check: if the message type is `url_check`, use `run_in_executor`; otherwise call directly.

   ```python
   handler = handlers.get(msg_type)
   if handler:
       if msg_type == 'url_check':
           loop = asyncio.get_running_loop()
           return await loop.run_in_executor(None, handler, data)
       else:
           return handler(data)
   ```

WHY only url_check: The other handlers (`_handle_ping`, `_handle_user_auth`, `_handle_get_user`, `_handle_user_signout`) are pure dict operations with no I/O. Only `_handle_url_check` calls `scan_service.check_url()` which does synchronous ZMQ REQ/REP that blocks for up to 5 seconds.

PITFALL to avoid: Do NOT use `loop.run_in_executor(None, handler(data))` -- this calls handler immediately in the current thread. The correct form is `loop.run_in_executor(None, handler, data)` which passes the function and argument separately. Since `_handle_url_check` takes a single `data` dict argument, this works directly without `functools.partial`.

Do NOT change any handler signatures or behavior. Do NOT wrap the other handlers in executors. Do NOT add any new handler methods.
