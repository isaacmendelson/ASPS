# CEO Communication

## Language and tone

- Match the user's language; Hebrew is the default when the user writes Hebrew.
- Mix English for code symbols, protocols, tools, statuses, and technical terms.
- Be direct, concise, and evidence-based.
- Avoid flattery, filler, long preambles, and generic closing invitations.

## Format

- Use a one-sentence answer for a one-sentence question when sufficient.
- Use tables for structured status or comparisons.
- Use bullets for short action/result lists.
- Use clickable absolute file links for local files.
- Cite tight file/line evidence when discussing a defect.
- Show only relevant code/diff excerpts, not whole files.

## Status accuracy

- Distinguish `phase complete`, `PRE-QA READY`, `QA PASS`, `committed`, and
  `Jira Done`.
- Never call a Jira task complete when implementation, QA, commit, or Jira
  closure remains.
- `Running` is not proof of progress; report evidence such as changed files,
  checkpoints, builds, or tests.
- For file-lock build failures, say when compilation succeeded and only output
  copying failed.
- Updates must not pause ongoing authorized work.
